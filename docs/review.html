IS117 / REAL PEER REVIEW

Inspect the evidence, not just the design.

For the current individual portfolio research round, each classmate should file 3–5 constructive GitHub issues. These must come from actual review, not invented feedback. The separate T-shirt project requires its own issues.

Reviewer tasks

  1. Find the research question in the research record.
  2. Open an original source and identify what it actually supports.
  3. Find one observed fact and one assumption about the audience.
  4. Trace a finding to a proposed feature and its acceptance check.
  5. Compare the project-first and career-story-first options and explain the current choice.
  6. Try the site on mobile or a narrow browser, including the menu.

Constructive issue format

Title: [Area] Specific issue or improvement. Body: What you attempted; what you observed; why it matters to the audience; one concrete improvement; how to verify the fix. Attach a screenshot or link if relevant, but avoid private data.

Author response workflow

  1. Read the actual issue and reproduce the observation.
  2. Comment with a decision: accept, adapt, or decline, and why.
  3. Link the changed documentation or code commit if a change is made.
  4. Record the verification steps and observed results.
  5. Ask for a retest when appropriate and close the issue with a concise resolution.
