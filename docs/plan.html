IS117 / PORTFOLIO DOCUMENTATION

Research → Plan → Build → Improve

This is a living project record. The initial implementation is not evidence of completed peer reviews or A/B testing.

Audience and purpose

Primary readers: internship recruiters, mentors, classmates, and instructors. Goal: help them understand my interests, technical skills, project evidence, and development process.

Two approaches

Option A: Project first

Lead with case studies and repositories. Benefit: evidence is immediate. Risk: early case studies may be incomplete.

Option B: Career story first

Lead with interests, skills, and then evidence. Benefit: explains direction. Risk: may be too text-heavy.

Initial choice: a hybrid: career-focused opening, followed by projects and public documentation. This choice is provisional until peer feedback.

Checkable user stories

  1. As a recruiter, I want to identify my career interests quickly. Check: the homepage clearly names AI engineering and cybersecurity.
  2. As a reviewer, I want to find project evidence. Check: the project area contains at least one working repository link and labels unfinished case studies.
  3. As a classmate, I want to understand a design decision. Check: this plan compares two approaches and explains the current choice.
  4. As a mobile visitor, I want working navigation. Check: at phone width the menu opens, closes, and links reach sections.
  5. As a mentor, I want accurate skill claims. Check: established tools are distinguished from skills still being learned.

Essential features

Responsive homepage, About, Skills, Projects, Career Research, GitHub links, public documentation, keyboard-friendly navigation, and clear project statuses.

Voice and honest persuasion

Professional, curious, and direct. Show real repository evidence instead of unsupported claims; clearly mark planned projects instead of pretending they are finished.

A/B build plan

Planned version A: project-first workflow. Planned version B: career-story-first workflow. A classmate will try the same task on each and compare ease of finding a project and understanding the career direction. A/B testing is not yet completed.

Feedback → change → retest

Pending: obtain real classmate feedback, create a GitHub issue, respond with a reasoned decision, implement a meaningful change, link the commit, and have the reviewer retry the task. Do not report these as completed until evidence exists.

Verification

Pending independent checks: test GitHub Pages links, desktop and mobile layouts, keyboard navigation, and accurate content. Record actual observed results and any fixes.

Course submission

Keep the full 250–350-word career reflection and personal eligibility details private in Canvas. This public record holds suitable professional goals, research decisions, and project evidence. Submit the correct URLs in Canvas.
