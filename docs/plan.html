Project plan

Original sources and research evidence ↗ · Peer review and issue workflow ↗ · Source repository ↗

1. Goal and audience

Question: How can I show credible technical work while exploring Forward Deployed Engineering and Software Engineering?

Readers: recruiters, mentors and classmates (proposed personas, not surveyed). They should find projects, original sources and clear progress labels.

2. Evidence and assumptions

Evidence: Baidu's FDE and C3 AI's SWE postings emphasize coding, problem-solving and communication. NIST and OWASP offer additional guidance.

Assumptions to test: visitors prefer projects near the top, understand the skills list and can navigate easily on mobile.

3. Design choices

Project-first

Shows evidence quickly, but unfinished projects stand out.

Career-story-first

Explains goals, but delays project links.

Chosen: hybrid

Short introduction, skills, projects, then career research. This is a design choice, not a tested result.

4. Evidence → feature → check

  1. Employer postings: coding and debugging → show project links and future case studies → verify code and test evidence when available.
  2. Baidu FDE: AI/API integration → plan an API demo → check loading, success and error states once built.
  3. C3 AI SWE: maintainable software → plan architecture and testing notes → check that another reader can follow and reproduce a test.
  4. NIST / OWASP: responsible AI and security guidance → document limitations and avoid unsupported expertise claims → review published wording.

5. Reader checks

  1. Recruiter: identify career interests quickly.
  2. Classmate: open an original job posting and trace it to a planned feature.
  3. Mobile visitor: use the menu and reach each section.
  4. Mentor: distinguish completed work from plans.

6. Build and review

Built with HTML, CSS and JavaScript. Research and planning updates are documented in GitHub commits. Peer feedback, decisions and retests must be recorded from actual activity; no unperformed tests are claimed.

AI assisted with drafting and implementation. Personal reflection stays in Canvas; proposed work is not presented as completed.
